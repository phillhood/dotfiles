# Grill

Interview relentlessly until you and the user reach shared understanding of the thing they already have in mind. This produces no artifact and starts no work — it exists to find what hasn't been thought through.

## How

**Walk the decision tree in dependency order.** Settle what everything else rests on first. A question answered out of order gets re-answered when its premise moves.

**One question per message.** Several at once is bewildering, and the user ends up answering the easy one and dropping the rest.

**Recommend an answer to every question** — the option you'd pick, one line on why it beats the alternative, and what it costs. A question with no recommendation makes the user do all the work.

**Facts you can find, find.** If the filesystem, the git history, a tool, or the docs can answer it, go and look. Only decisions go to the user — those are theirs, and you wait for each one.

**Follow the weak point.** When an answer exposes something unresolved, go there next rather than continuing down your prepared list.

## Finishing

**Don't act until the user confirms you've reached shared understanding.** The temptation at the end of a good interview is to start building, because it now feels obvious. Say what you understand and ask whether that's right.

If it turns into real work, hand to `workflow:spec` — the design still needs writing down and approving.
